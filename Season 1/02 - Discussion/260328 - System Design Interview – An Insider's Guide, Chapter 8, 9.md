## 주제별 요약

### 단축 URL 설계

- 단축 URL 서비스의 기본 API 구성
  - POST 요청으로 원본 URL을 단축 URL로 변환하는 엔드포인트와 GET 요청으로 단축 URL을 원본 URL로 리디렉션하는 엔드포인트 필요
  - 리디렉션 시 301(영구 이동)과 302(임시 이동) 상태 코드 사용 차이와 장단점 설명
- 해시 함수와 충돌 처리 방법
  - 해시 함수는 숫자와 영문 대소문자 62개를 기반으로 하며, 충돌 발생 시 추가 문자를 덧붙이는 방식 사용
  - 체이닝, 오픈 어드레싱 등 충돌 해소 기법과 각각의 탐색 시간 및 오버헤드 문제 언급
  - 블룸 필터 도입으로 메모리 효율적 중복 검사 가능, 100% 정확하지는 않으나 위양성만 존재하는 특성 설명
- 데이터 저장 및 캐싱 전략
  - 단축 URL과 원본 URL 매핑을 위한 유니크 ID 저장
  - 접근 빈도 차이에 따른 캐시 활용의 중요성 강조, 바이럴 URL에 대한 빠른 응답 필요성
- URL 길이 및 보안 고려
  - 베이스 62 변환을 통한 URL 길이 단축과 가변 길이 특성
  - 인크리멘탈 방식의 단순 ID 증가가 보안상 추측 가능성 문제 발생
- 서비스 요구사항과 트래픽 규모
  - 일억 개 이상의 URL 단축 처리 필요성
  - 문자 제한, 삭제 및 갱신 불가 문제와 서비스별 정책 차이
  - 초당 읽기/쓰기 연산량과 저장 용량 산정

### 크롤링 시스템과 중복 처리

- 크롤링 아키텍처 구성
  - 초기 URL 설정, IP 주소 변환, HTML 다운로드 및 URL 추출 과정
  - 중복 URL 검사 및 방문 여부 판단을 위한 저장소와 블룸 필터 활용
  - 우선순위 큐를 통한 크롤링 대상 URL 선정과 호스트별 요청 제한 및 딜레이 적용
- 중복 콘텐츠 및 스파이더 트랩 대응
  - 전체 웹 콘텐츠 중 약 30%가 중복 콘텐츠임을 인지하고 중복 제거 필요
  - 무한 반복 URL 생성(스파이더 트랩) 방지 및 의미 없는 광고, 프레임 필터링
- 크롤링 데이터 저장 및 확장성
  - 텍스트, 이미지, 동영상 등 다양한 콘텐츠 유형에 대응 가능한 플러그인 구조 제안
  - 대용량 데이터 다운로드와 처리 분리, 배치 처리 방식의 효율성
- 크롤링 환경과 제한 사항
  - 자바스크립트가 많은 페이지 처리, 스크롤 다운 등 동적 콘텐츠 대응 필요성
  - 디도스 방지 및 요청 제한 정책 준수
  - 로봇 배제 표준(robots.txt)과 사이트별 크롤링 정책 준수

### AI 시대와 개발 환경 변화

- AI 의존도 증가와 사고력 저하 우려
  - 클라우드 AI 서비스 장애 시 사용자 작업 불가 사례 언급
  - 생성형 AI 모델의 전략 자산화 가능성과 국가별 규제 전망
- AI와 개발 업무 변화
  - AI가 코딩 테스트 및 과제형 문제 해결에 활용되는 현실
  - AI가 단순 수정 작업을 수행하지만, 잘못된 수정 위험성 존재
- 기본기와 설계 역량 중요성 강조
  - AI 시대에도 시스템 설계와 기본기 능력이 더욱 중요해짐
  - 운영체제, 시스템 설계 교육의 필수화 필요성 제기
- 오픈소스 기여와 취업 영향
  - 오픈소스 컨트리뷰터 활동이 취업 시장에서 큰 영향력 발휘
  - 리뷰어 부족과 AI 활용에 따른 코드 품질 문제 발생
