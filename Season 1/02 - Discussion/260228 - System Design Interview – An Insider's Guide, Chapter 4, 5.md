## 주제별 요약

### 안정 해싱과 서버 증설 문제

- 기존 해시 테이블 방식의 서버 인덱스 계산 문제
  - 서버 증설이나 장애 발생 시 N 값 변경으로 인해 전체 해시 값이 바뀌어 다른 서버에 영향 발생
  - 이로 인해 데이터 재배치와 캐시 미스가 빈번하게 발생하는 문제
- 안정 해싱 알고리즘 적용
  - 서버와 키를 해시 링에 배치하고 일관된 방향(주로 시계 방향)으로 서버를 선택하는 방식
  - 서버 추가 시 일부 키만 재배치되어 전체 재배치 비용 감소
  - 서버 제거 시에도 영향 받는 키 구간이 제한적임
- 안정 해싱의 한계와 개선점
  - 서버 간 파티션 크기 불균형 문제 발생 가능성
  - 서버 성능 차이를 반영하지 못하는 점
  - 버추얼 노드 사용 시에도 노드 성능 차이나 장애 발생 시 재배치 비용 문제 존재
  - 가중치 기반 해싱(예: 랜덤 웨이트 해싱) 도입으로 일부 문제 완화 가능
- 실제 적용 사례 및 운영 환경
  - 차량 데이터, 게임 서버 등 대규모 분산 환경에서 서버 부하 균등 분배 중요
  - 오토스케일링 환경에서 서버 증감에 따른 동적 재배치 필요성
  - 장애 발생 시 락 문제와 레이턴시 증가 우려

### 게임 및 클라우드 서버 운영

- 게임 서버의 수평 확장과 세션 관리 어려움
  - 게임은 특정 서버에 세션이 고정되어야 하며, 수평 확장이 쉽지 않음
  - 글로벌 서버 간 통신 및 레이턴시 문제 존재
  - 게임 서버는 자체 서버 운영이 많고 클라우드 사용은 제한적
- 클라우드 환경과 CDN, P2P 활용
  - CDN 비용 부담과 트래픽 급증 시 CDN 한계 존재
  - P2P 방식으로 CDN 부담 완화 시도 사례
  - 클라우드 서버 위치 선정과 네트워크 최적화 중요
- 서버 장애 대응 및 세션 유지
  - 서버 장애 시 세션 재배치 및 접근 경로 변경 필요
  - 게이트웨이 레벨에서 서버 선택 및 트래픽 분배 처리
  - 게임과 일반 웹 서비스 간 세션 처리 방식 차이

### 처리율 제한과 보안 대책

- 처리율 제한 장치의 종류와 위치
  - 클라이언트, 서버, 중간 API 리듀서 등 다양한 위치에서 적용 가능
  - 클라이언트 적용 시 리센스 문제, 서버 적용 시 별도 기능 필요
- 처리율 제한 알고리즘
  - 토큰 버킷, 고정 윈도우 카운터, 이동 윈도우 카운터 등 다양한 방식 존재
  - 이동 윈도우 카운터는 요청 로그를 저장해 처리 가능 여부 판단
  - 처리 실패 로그 저장과 재시도 문제 존재
- 디도스 방어와 트래픽 제어
  - 디도스 방어 장비는 서버 하위 레이어에서 주로 운영
  - 클라우드 서비스와 통신사 협력으로 공격 차단 가능
  - API 게이트웨이 단계에서 비정상 트래픽 차단 및 라우팅 처리
- 보안 및 사용자 오용 대응
  - 클라이언트와 서버 양쪽에서 제한 및 방어 코드 적용
  - 금융권 등 민감 영역에서 API 보안 강화 필요
  - 사용자 오용 사례 증가에 따른 제한 장치 중요성 부각
- 로그 및 모니터링 활용
  - 비정상 트래픽 및 과도한 요청에 대한 IP 차단 및 모니터링
  - 로그 저장과 분석을 통한 보안 강화
  - 처리율 제한 실패 시 로그 기반 대응 방안 검토

### 데이터베이스 샤딩과 비정규화

- 샤딩 적용 시 고려사항과 어려움
  - 데이터 분산 저장으로 인한 복잡도 증가와 운영 난이도 상승
  - 샤딩 적용 후 되돌리기 어려움
- 비정규화의 역할과 한계
  - 조인 비용 절감과 데이터 접근 속도 향상을 위해 사용
  - 과도한 비정규화는 데이터 일관성 문제 야기
- 실제 운영 사례
  - 대규모 게임 및 서비스에서 샤딩과 비정규화 병행 적용
  - 샤딩은 최후의 수단으로 인식되며 신중한 적용 권장
