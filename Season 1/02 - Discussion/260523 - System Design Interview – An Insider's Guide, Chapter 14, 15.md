## 주제별 요약

### 유튜브 설계

- 유튜브 시스템의 기본 범위 설정
  - DAU 500만, 동영상 최대 300MB 업로드, 실시간 스트리밍과 VOD 재생 지원
  - 동영상 업로드, URL 발급, CDN 기반 스트리밍, 메타데이터 관리 포함
- 업로드 기능 세부 요구사항
  - 청크 단위 업로드 및 레주머블(중단 후 재개) 지원
  - 제목, 설명, 태그 입력 및 업로드 상태 조회 기능
  - 업로드 완료 후 자동 트랜스코딩 시작, 다양한 해상도 및 비트레이트 지원
  - 썸네일 추출, 자막 및 오디오 트랙 관리, 실패 시 재시도 및 실패 원인 기록
- 재생 기능 요구사항
  - 비디오 메타데이터 조회, 매니페스트 URL 발급, 세그먼트 단위 재생 지원
  - 네트워크 상태에 따른 자동 화질 조절, 권한에 따른 영상 접근 제어
  - 재생 중 끊김 최소화, 품질 선택 및 자동 저장 기능
- 인프라 및 확장성 고려사항
  - 인기 동영상 급증 시 확장성 확보, 고가용성 설계 필수
  - 저장 용량 증가에 따른 비용 최적화, 보안 강화
- 업로드 및 트랜스코딩 처리 아키텍처
  - API 게이트웨이 통한 인증, 레이트 리밋, 라우팅 처리
  - 업로드 세션 생성, 청크 수신, 체크섬 검증, 원본 확정, 트랜스코딩 큐 등록 및 비동기 처리
  - 트랜스코딩은 DAG(Directed Acyclic Graph) 기반 병렬 처리, 토폴로지컬 스케줄링 적용
  - CPU/GPU 워커 관리 및 우선순위 제어
- 업로드 실패 및 장애 대응
  - 재시도 횟수 제한, 실패 시 사용자 알림
  - 워커 재배치, 메타데이터 DB 페일오버, CDN 장애 시 멀티 CDN 활용 제한
- 재생 품질 및 UX
  - 적응형 비트레이트 스트리밍 지원하나, 고정 화질 선호 경향 존재
  - 썸네일 및 매니페스트 파일 캐싱 최적화
- 데이터 모델 및 DB 설계
  - 유저, 비디오, 에셋, 업로드 세션, 트랜스코딩 잡 테이블 구성
  - 타임스탬프는 유닉스 타임스탬프(I64) 사용, UTC 기반 권장
  - 인기 크리에이터 트래픽 집중 완화 위한 타임 버킷 및 캐시 전략 적용
- 로그 및 모니터링
  - 업로드 성공률, 실패율, 지연 시간 등 지표 수집 및 대시보드 제공
  - 재생 이벤트 로그 수집, 추천 알고리즘용 사용자 행동 데이터 처리
- 콘텐츠 검수 및 보안
  - 권한 설정, 연령 제한, 링크 공유 제어
  - 악성 콘텐츠 차단, 바이러스 스캔, 2차 저작권 침해 탐지 AI 활용

### 구글 드라이브 설계

- 기본 기능 및 요구사항
  - 파일 업로드, 다운로드, 공유, 노티피케이션 지원
  - 최대 파일 크기 10~100GB, DAU 약 1000명 규모
  - 모바일 및 웹 동시 지원, 암호화 필수
- 데이터 무결성 및 신뢰성
  - 데이터 유실 불가, 법적 책임 가능성 존재
  - 업로드 유지 및 유실 방지 위한 보안 및 검증 절차 강화
- 파일 동기화 및 충돌 처리
  - 기기간 자동 동기화 및 변경 알림(노티피케이션)
  - 동시 편집 시 충돌 발생 시 충돌 버전 별도 저장 후 사용자 선택 병합
- API 및 데이터 처리
  - 파일 업로드 POST API, 청크 단위 분할 업로드 지원
  - 메타데이터 조회 및 갱신, 파일 버전 관리
  - 롱폴링 기반 단방향 알림 서비스 사용, 웹소켓은 오버스펙으로 평가
- 저장소 및 인프라 구성
  - 청크 단위 압축, 암호화 후 저장, 독립 개체로 관리
  - 메타데이터 DB는 확장성 위해 샤딩, 리플리케이션 적용
  - 단일 장애점 방지 위한 서버 무리 및 복수 서버 분산 처리
- 장애 및 확장성 대응
  - 메타데이터 서버 과부하 시 목록 조회 불가 사례 존재
  - 동기화 충돌 및 버전 관리로 데이터 일관성 유지
  - 장애 발생 시 워커 재배치, 페일오버, 캐시 활용 등 대응
- 저장소 최적화
  - 중복 제거를 통한 저장 공간 절감
  - 버전 수 제한 및 중요 버전 선택적 보존 정책
  - 콜드 스토리지 활용으로 비용 절감
- 오브젝트 스토리지 및 블록 스토리지
  - CEPH, 쉐프(Ceph) 등 오픈소스 오브젝트 스토리지 활용
  - 데이터 청크를 블록 단위로 분할 저장, RAID 유사 방식으로 내결함성 확보
  - 오픈스택 기반 클라우드 인프라와 연동
- 동시 편집 및 버전 관리
  - CRDT 등 동시 편집 기술 적용 사례 언급
  - 동시 편집 구현 난이도 높음, 대학생 실습에 적합
- 노티피케이션 및 실시간 동기화
  - 변경 사항 실시간 알림, 오프라인 시 재접속 후 변경분 동기화
  - 단방향 알림으로 구현 단순화
- 데이터 모델 및 API 설계
  - 유저, 파일, 블록, 버전, 워크스페이스 등 테이블 구성
  - API 서버는 복수 서버 분산 처리, 클라이언트는 변경된 부분만 조회
- 장애 처리 및 모니터링
  - 업로드 중단 시 체크섬 재검증, 재시도 제한
  - 메타데이터 DB 장애 시 페일오버 및 캐시 활용
  - 로그 수집 및 분석 통한 서비스 안정성 확보
- 학습 및 실습 권장
  - 대용량 업로드 및 동시 편집 시스템 직접 구현 시 학습 효과 큼
  - 오픈소스 스토리지 및 클라우드 인프라 활용 사례 소개
