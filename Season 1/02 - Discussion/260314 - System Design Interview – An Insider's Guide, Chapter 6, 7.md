### 분산 ID 설계 요구사항

- 유일성, 시간 순 정렬, 64비트 크기 제한, 고성능 요구사항
  - ID는 분산 환경에서 중복 없이 유일해야 하며, 시간 순서대로 정렬 가능해야 함
  - 64비트 이하 크기 제한과 초당 최대 만 개 이상 생성 가능해야 함
- 분산 환경에서 단일 서버 ID 생성 한계와 분산 ID 필요성
  - 단일 서버 환경에서는 중복 문제 없으나, 분산 서버 환경에서는 유니크 ID가 필수
  - 분산 ID는 여러 서버에서 생성된 데이터를 식별하고 관리하는 데 필요
- 요구사항 명확화를 위한 인터뷰 및 질문 과정 강조
  - 설계 전 명확한 요구사항 파악을 위해 인터뷰를 통한 상세 질문 필요성

### 분산 ID 생성 방법 비교

- 멀티마스터 방식
  - 서버 수만큼 증가값을 나누어 홀수, 짝수 등으로 분배해 ID 생성
  - 확장성 제한, 서버 추가/제거 시 관리 복잡성 존재
  - 시간 순 증가 보장 어려움
- UUID 방식
  - 128비트 랜덤 기반 ID 생성, 서버 간 조율 불필요
  - 충돌 확률은 극히 낮으나 완전 배제 불가
  - 64비트 제한과 시간 순 정렬 요구에는 부적합
- 티켓 서버 방식
  - 중앙 집중형 단일 서버에서 ID 발급 관리
  - 단일 장애점(SPOF) 문제 존재, 대규모 확장 어려움
- 스노플레이크 방식
  - 64비트 ID를 시간, 서버 위치, 시퀀스 번호로 분할하여 생성
  - 분산 생성 가능, 시간 순 정렬, 고성능 충족
  - 서버 위치 식별자 최대 1024개 지원, 초당 4096개 생성 가능

### 스노플레이크 ID 구조 및 생성 과정

- 64비트 구성
  - 상위 비트는 예약 비트, 중간은 UTC 기준 시간(밀리초 단위), 하위는 서버 위치 및 시퀀스 번호
  - 시간 기준은 1970년이 아닌 특정 기준일로 조정 가능해 확장성 확보
- ID 생성 과정
  - 현재 시간 샘플 획득 후, 서버 위치 및 시퀀스 번호와 조합
  - 동일 밀리초 내 4096개 초과 시 밀리초 단위로 밀어 생성
- 시간 역행 문제 및 보완책
  - 시계 불일치, 시간 역행 가능성 존재
  - NTP, 클러리(고정 NTP) 등 시간 동기화 방법 활용
  - 역행 감소 라이브러리 및 정책 적용 필요

### 분산 시스템 장애 처리 및 데이터 일관성

- CAP 이론 적용과 CP, AP 모델 설명
  - CP는 일관성 우선, 장애 시 일부 노드 쓰기 금지, 금융권 등에서 사용
  - AP는 가용성 우선, 장애 시에도 데이터 사용 가능, 일부 서비스에 적합
- 데이터 버전 관리 및 충돌 해결
  - 데이터 버전링, LWW(최신 시간 우선), 백퍼 클럽 등 충돌 방지 기법 적용
  - 장애 감지 및 서버 간 투표를 통한 임시 복구 가능
- 장애 감지 및 처리 프로토콜
  - 헬스 체크, 머플 트리, 가십 프로토콜 등 다양한 장애 감지 및 처리 방법 활용
  - 영구 장애와 일시 장애 구분하여 대응
- 데이터 센터 장애 대비 및 DR 구성
  - 다중 데이터 센터 운영, DR(재해 복구) 구성 필요성
  - 비용과 운영 복잡성 고려한 설계 필요
