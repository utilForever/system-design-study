## 주제별 요약

### 위치 측정 시스템

- GPS, 와이파이, 신호 수신 등 다양한 수단으로 사용자 위치 측정
  - 위치 정보는 단말에서 주기적으로 서버로 전송되며, 1초~15초 간격으로 위치 변경 이력 저장
  - 위치 데이터는 도로 상황 모니터링, 개인화 경험, 예상 도착 시간 계산 등에 활용
- 위치 데이터 저장 및 처리 시스템
  - 카산드라 같은 분산 데이터베이스를 사용해 대량의 위치 데이터를 효율적으로 저장
  - 카프카를 이용해 이벤트 순서대로 기록하고, 스트리밍 처리로 실시간 데이터 활용
  - 메모리 용량 제한과 디스크 공간 부족 문제로 데이터 병합 및 압축 처리 필요
- 데이터 손실과 저장 공간 문제
  - 인터넷 불안정 지역에서는 메모리 기반 저장으로 데이터 유실 가능성 존재
  - 데이터 머지 기법을 통해 오래된 데이터 우선 유지하며 공간 효율화 시도

### 지도 표시 및 타일 시스템

- 지도 데이터는 벡터 및 이미지 타일 형태로 분할 저장
  - 타일은 계층적 분할되어 클라이언트에서 확대/축소 시 효율적 렌더링 가능
  - CDN을 통해 전 세계 사용자에게 지도 타일을 빠르게 제공하며 서버 부하 감소
- 지도 타일 갱신 및 캐싱 전략
  - 지도 데이터 갱신 주기는 느리며, 변경된 타일만 부분적으로 교체
  - 사용자 기기 내 캐싱으로 데이터 사용량과 트래픽 절감
- 대용량 저장소 요구
  - 전 세계 지도 이미지 및 벡터 데이터 저장에 페타바이트 단위 저장소 필요
  - 압축 기술로 80~90% 데이터 용량 감소 가능

### 경로 안내 및 알고리즘

- 경로 안내를 위한 도로 데이터 가공
  - 원시 도로 데이터는 그래프 형태로 가공되어야 하며, 대규모 데이터는 격차 분할 기법으로 처리
  - 그래프는 지역 단위로 분할해 골목길부터 고속도로까지 계층적 탐색 지원
- 경로 탐색 알고리즘
  - 자동차 경로 탐색에는 다익스트라 알고리즘 기반 캐싱과 격차 분할 활용
  - 대중교통 경로 탐색은 다익스트라 비효율적이며, RAPTOR 등 교통공학 기반 알고리즘 적용
  - 요금, 환승 등 복잡한 조건을 고려하는 변형 알고리즘 McRAPTOR 사용
- 실시간 교통 상황 반영
  - 사고, 공사 등 교통 상황 변화는 즉각적으로 반영되어 경로 재탐색에 활용
  - 과거 및 현재 교통 데이터 기반 예상 도착 시간(ETA) 계산
- 경로 안내 서비스 구성
  - 지오코딩을 통해 주소를 좌표로 변환 후 경로 탐색에 활용
  - 경로 후보 리스트 생성 후 비용, 유료 도로, 계단 등 조건으로 필터링해 최적 경로 제공

### 데이터 저장 및 처리 인프라

- 대용량 데이터 저장소 및 처리
  - 지도 이미지, 경로 안내 파일, 위치 데이터, 지오코딩 데이터 등 다양한 데이터 유형별 저장소 분리
  - S3 같은 객체 저장소에 그래프 데이터 직렬화 저장, 카산드라에 위치 데이터 저장
- 데이터베이스 특성 및 선택
  - 카산드라는 쓰기 성능 우수하며, 분산 환경에서 데이터 중복 허용 및 일관성 완화 전략 사용
  - SQL과 NoSQL 혼용으로 중요도에 따른 데이터 분리 저장
- 메시징 및 이벤트 처리
  - ZeroMQ는 별도 브로커 없이 애플리케이션 간 메시지를 빠르게 전달하는 경량 메시징 라이브러리로, 낮은 지연 시간이 중요한 내부 통신에 적합
  - RabbitMQ는 AMQP 기반 메시지 브로커로, 메시지 확인·재시도·복잡한 라우팅을 지원해 신뢰성 있는 작업 큐와 서비스 간 비동기 통신에 적합
  - MQTT는 저대역폭·불안정한 네트워크를 고려한 경량 발행-구독 프로토콜로, 모바일 단말이나 IoT 기기의 위치·상태 전송에 적합
  - 카프카는 분산 커밋 로그 기반 이벤트 스트리밍 플랫폼으로, 대규모 위치 이벤트를 순서대로 영속화하고 여러 소비자가 실시간·재처리하는 데 적합
- 데이터 처리 최적화
  - 데이터 중복 제거, 변경 이력 관리, 배치 처리로 쓰기 부하 완화
  - JSON 패치 방식으로 변경된 데이터만 전송해 네트워크 효율화

### 서비스 운영 및 보안 이슈

- 대규모 사용자 기반 서비스 운영
  - DAU 10억 명 이상, 주당 평균 35분 사용 가정으로 엄청난 쓰기 및 쿼리 요청 발생
  - 로드밸런서와 CDN을 통한 부하 분산 및 빠른 응답 보장
- 크롤링 및 데이터 무단 수집 방지
  - 디지털 프린팅, 페이크 인식, CAPTCHA 등 다양한 방어 기법 논의
  - 매크로 및 자동화 공격과의 전쟁으로 사용자 경험과 보안 간 균형 필요
- 민감 지역 및 데이터 확보 문제
  - 군사 지역, 분쟁 지역 등에서 지도 데이터 확보 어려움 존재
  - 지역별 특성에 맞는 데이터 확보 및 서비스 대응 필요
- 앱 검수 및 업데이트 이슈
  - 클라이언트 내 경로 탐색 알고리즘 변경 시 앱스토어 검수 지연 문제
  - 서버 기반 알고리즘 서비스화로 클라이언트 부담 완화 방안 고려
