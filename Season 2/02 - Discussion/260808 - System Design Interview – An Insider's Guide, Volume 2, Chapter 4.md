## 주제별 요약

### 메시지 큐 개념과 활용

- 메시지 큐의 다양한 활용 범위
  - 클라이언트 내부 서비스 간 데이터 전달, 클라이언트서버 간 통신, 서버 내부 메시지 처리 등 다양한 시나리오에서 사용
  - 목적에 따라 메시지 보관 기간, 전달 보장 방식, 순서 보장 여부 등이 달라짐
- 메시지 큐 설계 시 고려사항
  - 메시지 보관 기간 설정 필요, 즉발성 메시지와 장애 대비 메시지 보관 구분
  - 메시지 전달 보장 방식(최대 한 번, 최소 한 번, 정확히 한 번) 선택
  - 메시지 순서 보장 범위 결정(글로벌 오더링, 키 기반 오더링)
- 메시지 큐의 기본 동작
  - 생산자는 토픽에 메시지 발행, 소비자는 토픽 구독 후 오프셋 기반으로 메시지 소비
  - 토픽은 여러 파티션으로 나뉘어 확장성과 병렬 처리 지원
  - 같은 컨슈머 그룹 내에서는 파티션을 분배해 병렬 소비 가능

### 복제와 파티션 관리

- 복제의 목적과 방식
  - 데이터 유실 방지와 장애 대응을 위해 리더 브로커가 데이터를 받고 팔로워 브로커에 복제
  - 복제 완료 시점에 따라 ACK 정책(0, 1, all) 선택 가능하며, 각 정책은 레이턴시와 안정성에 영향
- 파티션과 브로커 역할
  - 파티션은 메시지 저장 및 순서 보장 단위로, 여러 브로커에 분산 저장
  - 브로커는 파티션 상태 모니터링, 리더 선출, 복제 관리 담당
  - 리더 장애 시 팔로워 중 새 리더 선출로 서비스 연속성 확보
- 파티션 수 조정과 병렬성
  - 파티션 수가 많으면 병렬 처리와 저장 분산에 유리하나 메타데이터 관리 비용 증가
  - 파티션 재설계, 프로듀서 쿼터 조정 등으로 부하 분산 가능

### 메시지 저장과 처리 방식

- 로그 기반 저장과 오프셋 관리
  - 메시지는 순차적 로그 파일에 기록되며, 오프셋으로 위치 관리
  - 로그는 세그먼트 단위로 분할 저장해 파일 손상 시 영향 최소화
  - 랜덤 액세스 대신 순차 기록과 오프셋 기반 접근으로 성능 최적화
- 배치 처리와 소비 속도 조절
  - 배치 처리는 처리량 증가 목적이나 레이턴시 증가 단점 존재
  - 일정 개수 또는 시간 기준으로 배치 전송하며, 임베디드 등 레이턴시 민감 환경에서는 비선호
  - 소비자는 폴링 주기와 버퍼 크기 조절로 처리량과 레이턴시 균형 조절 가능
- 메시지 중복과 유실 처리
  - 최소 한 번(At Least Once) 처리 시 중복 가능성 존재, 유실 방지 우선
  - 최대 한 번(At Most Once) 처리 시 중복 없음, 유실 가능성 존재
  - 정확히 한 번(Exactly Once) 처리는 구현 난이도 높으며, 주로 금융 등 중요 서비스에 적용

### 장애 대응과 운영 전략

- 장애 유형과 대응
  - 프로듀서, 브로커, 컨슈머, 다운스트림 장애 모두 발생 가능
  - 브로커 장애 시 리더 재선출과 리밸런싱으로 서비스 지속
  - 컨슈머 장애 시 하트비트 타임아웃으로 감지 후 재배치
  - 다운스트림 장애는 외부 요인으로 직접 제어 어려우며, 재시도 정책과 장애 격리 필요
- 메시지 큐 내 중복 처리 전략
  - 중복 처리 완전 방지는 어려우며, ID 기반 중복 검출과 해시 비교 등으로 완화 시도
  - 프론트엔드와 백엔드 모두 중복 요청 방어를 위한 이중 방어 체계 필요
- 모니터링과 운영
  - 레이턴시, 처리량, 디스크 사용량, 네트워크 상태, 복제 상태 등 다양한 지표 모니터링 필수
  - 경고 시스템은 과도한 알람 방지와 신속 대응 균형 필요
  - 장애 원인 분석과 대응 프로세스 마련 중요

### 메시지 큐 기술 동향과 환경

- 메시지 큐와 관련 기술 변화
  - 과거 주키퍼와 메시지 큐가 분리되어 있었으나, 최근에는 메타데이터 관리가 메시지 큐 내부로 통합되는 추세
  - 리액티브 프로그래밍과 메시지 큐의 개념이 유사하게 융합되는 경향
- 저장 매체와 비용 변화
  - 하드디스크는 순차 기록 시 성능 우수, 랜덤 액세스가 느린 주요 원인
  - SSD 가격 상승과 공급 부족 현상으로 저장 비용 증가
  - 클라우드 메모리 비용도 상승 중이며, 일부 클라우드는 메모리 사용에 별도 과금
- 메시지 큐 사용 환경과 사례
  - 게임, 금융, 미디어 등 다양한 분야에서 메시지 큐 활용
  - 게임에서는 클라이언트 변조와 무결성 문제로 서버와 클라이언트 간 복잡한 계산 분담 필요
  - 금융 분야는 중복 처리와 정확한 메시지 전달 보장이 특히 중요

### 소비자 그룹과 메시지 처리

- 컨슈머 그룹과 파티션 할당
  - 같은 컨슈머 그룹 내에서는 파티션을 1:1로 할당해 병렬 처리
  - 컨슈머 그룹 간에는 독립적으로 메시지 소비 가능해 장애 시 영향 최소화
- 메시지 재처리와 오프셋 커밋
  - 메시지 처리 후 오프셋 커밋으로 처리 완료 표시
  - 장애 발생 시 마지막 커밋 오프셋부터 재처리 가능
- 처리 보장 정책과 적용 사례
  - 최소 한 번 처리 정책은 중복 가능성 감수, 유실 방지 우선
  - 최대 한 번 처리 정책은 중복 없음, 유실 가능성 존재
  - 정확히 한 번 처리 정책은 구현 난이도 높아 금융 등 중요 서비스에 적용
- 중복 처리와 순서 보장
  - 전체 메시지 순서 보장이 필요한 경우 파티션 설계 시 별도 고려 필요
  - 중복 처리 완전 방지는 어려우며, 해시 비교 등으로 일부 완화 가능
