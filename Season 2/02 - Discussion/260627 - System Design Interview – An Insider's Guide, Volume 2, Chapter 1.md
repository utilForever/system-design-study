## 주제별 요약

### 시스템 요구사항

- 사용자 위치 기반 반경 내 사업장 목록 반환 기능
  - 카테고리 필터링, 상세 정보 조회, 정렬 기능 지원
  - 사업장 정보의 생성, 수정, 삭제 기능 포함하나 즉시 반영은 필수 아님
- 비기능 요구사항으로 낮은 지연 시간과 개인정보 보호 중요
  - 위치 정보는 휘발성 저장 또는 암호화 필요
  - GDPR 등 지역별 개인정보 보호법 준수 필수
- 트래픽 집중 현상 고려
  - 특정 지역, 시간, 이벤트 발생 시 트래픽 급증 예상
  - 고가용성 및 확장성 설계 필요

### 공간 인덱싱 기법

- 위경도 기반 단순 반경 검색의 한계
  - 도심과 시골 지역 간 데이터 밀도 차이로 후보군 수 편차 큼
- 격자(셀) 기반 분할 기법
  - 균등 격자: 구현 용이하나 데이터 불균등 분포 문제 존재
  - 지오해시(Geohash): 인접 셀을 접두사로 묶어 근접 후보군 추출 가능하나 경계 처리 어려움
  - 쿼드트리: 밀집 지역은 세밀하게, 희박 지역은 크게 분할해 효율적 조회 가능
    - 메모리 상주 필요, 재구축 시점과 무중단 갱신 고려해야 함
  - 구글 S2 라이브러리 등 외부 라이브러리 활용 가능하나 의존성 문제 존재
  - 한국과 같이 데이터 밀도가 높은 환경에서는 쿼드트리 선호 경향
    - 조회 속도 우선, 갱신 난이도는 운영 전략으로 보완

### API 설계 및 데이터 모델

- 주요 API는 검색(GET), 상세 조회(GET), 사업장 관리(CIUD)로 구성
- 검색 결과는 페이징 처리로 제한(예: 20개씩)
- 데이터 모델은 사업장 원본 테이블, 지오해시 인덱스 테이블, 영업시간 테이블, 카테고리 인덱스 테이블 등 4개 테이블 중심
- 검색 경로는 지오해시 기반 후보군 추출 후 상세 정보 조회 및 거리 계산, 정렬 순으로 진행

### 캐시 및 데이터 일관성

- 읽기 중심 시스템으로 캐시 활용 필수
  - 사업장 정보 변경은 비동기 처리 가능
- 캐시 무효화 전략
  - TTL 지터링 적용해 캐시 만료 시점 분산
  - 싱글 플라이트 기법으로 동일 쿼리 중복 DB 조회 방지
- 캐시 만료 동시 발생 시 과부하(캐시 미스드 스톰) 방지 필요
- 캐시 갱신 시점과 데이터 변경 시점 간 일관성 문제 고려
- 캐시 키 설계 시 위치 좌표의 미세 변동으로 인한 키 불일치 문제 존재

### 트래픽 분산 및 확장성

- 서버 측에서 후보군 추출 및 거리 계산 수행 권장
  - 클라이언트 처리 시 배터리, 성능 문제 발생 가능성 높음
- 수평 확장 가능한 스테이트리스 서비스 설계 필요
- 리전별 데이터 거주성 및 개인정보 규정 준수 고려
- 피크 트래픽 대응을 위한 로드 밸런싱 및 분산 처리 전략 필수

### 개인정보 보호 및 데이터 분석

- 위치 정보는 민감 데이터로 암호화 또는 휘발성 저장 권장
- 로그 데이터는 개인 식별 가능 정보 최소화 필요
  - 예: 구체적 주소 대신 구역 단위 집계 정보 활용
- 개인정보 보호법과 회사 정책에 따른 데이터 수집 범위 설정
- 분석 목적에 맞는 익명화 및 집계 데이터 활용 권장
- 사용자 동의 기반 데이터 수집 및 활용 중요성 강조

### 운영 및 실무 고려사항

- 쿼드트리 등 복잡한 자료구조 운영 난이도 높음
  - 재구축, 동시성, 무중단 배포 등 고려 필요
- 캐시 무효화 빈도 증가 시 비용 상승 문제 존재
- 실시간 반영 요구 시 별도 캐시 레이어 추가 및 TTL 조정 필요
- 대규모 동시 접속자 처리 위한 서버 증설 및 분산 전략 필수
- 설계 시 트레이드오프 인지 및 우선순위 설정 중요
- 경험 기반 설계와 반복 검증 과정 필요
